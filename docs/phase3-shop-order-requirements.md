# Phase 3 店铺与订单管理需求设计文档

> 版本：v1.0  
> 日期：2026-04-30  
> 状态：待评审  
> 适用范围：Sync Service 前端、Sync Service API、订单/店铺数据模型增强

---

## 1. 文档目标

本文档用于整理下一阶段店铺管理与订单管理的修改、新增内容，作为后续产品确认、接口设计、前端开发、后端开发和测试验收的统一依据。

当前系统已具备基础版店铺管理与订单列表能力，但仍存在以下问题：

- 店铺列表字段不足，缺少筛选、排序、授权状态展示和启停操作闭环。
- 订单列表字段过少，缺少状态标签栏、分页、批量勾选、批量操作和导出能力。
- 订单关键时间字段和订单状态定义尚未统一，容易在实现中出现口径不一致。

本阶段目标是将“店铺管理”与“订单列表”提升为可用于日常运营的标准页面。

---

## 2. 设计范围

本阶段包含以下范围：

- 店铺管理列表页改造。
- 店铺启停、编辑、授权/重新授权能力补充。
- 订单列表页改造。
- 订单状态标签筛选、字段展示、分页、批量勾选、批量操作。
- 订单 Excel 导出。
- 订单关键时间字段定义统一。
- 订单业务状态定义统一。

本阶段暂不包含以下内容：

- 订单详情页深度改造。
- 物流轨迹详情页。
- 全平台差异化状态页单独设计。
- 财务对账、售后、退款等独立业务模块。

---

## 3. 现状与改造目标

### 3.1 当前现状

当前系统已有：

- `店铺管理` 页面，可查看基础店铺信息、执行编辑、验证、备份、恢复、删除。
- `订单列表` 页面，可查看基础订单信息，并执行手动同步。

当前不足：

- 店铺页未按马帮 ERP 风格输出运营所需字段。
- 店铺页缺少按名称、平台、状态筛选和按表头排序能力。
- 店铺页缺少“授权状态”“Token 验证结果”“最后授权时间”“授权到期时间”等关键字段。
- 订单页无状态标签栏。
- 订单页无平台、交易号、付款时间快捷筛选。
- 订单页无分页、无勾选、无批量操作。
- 订单页字段不足，无法支持仓配履约使用。
- 订单导出字段与列表字段未统一设计。

### 3.2 改造目标

- 形成可运营的店铺列表页。
- 形成可运营的订单列表页。
- 统一订单状态、时间字段和展示口径。
- 为下一步订单详情、物流详情、批量履约能力打基础。

## 4. 店铺管理需求

### 4.1 页面目标

店铺管理页用于查看和维护各平台店铺的启用状态、授权状态和 Token 健康状态，并支持编辑、授权、重新授权、启用、停用等操作。

### 4.2 列表字段

店铺列表需展示以下字段：

| 字段 | 说明 |
|---|---|
| 店铺名称 | 店铺展示名称，优先显示 `display_name` |
| 平台 | 店铺所属平台，如 Ozon、Allegro、Wildberries |
| 状态 | 启用、停用 |
| 授权状态 | 成功、失败、未授权；默认值为“未授权” |
| Token 验证结果 | 文本展示，如“Token令牌授权成功”“令牌无效，请检查” |
| 最后授权时间 | 最近一次授权成功或重新授权成功时间 |
| 授权到期时间 | OAuth2 或平台令牌有效截止时间；无到期概念时可为空 |
| 创建人 | 创建该店铺记录的本地用户 |
| 创建时间 | 记录创建时间 |
| 操作 | 编辑、授权/重新授权、启用/停用 |

### 4.3 筛选条件

支持以下筛选：

- 店铺名称
- 平台
- 状态

筛选规则：

- 店铺名称支持模糊匹配。
- 平台使用下拉单选。
- 状态使用下拉单选，值为“启用”“停用”。

### 4.4 排序规则

点击表头可排序字段：

- 店铺名称
- 平台
- 状态

排序要求：

- 支持升序、降序切换。
- 默认排序建议为创建时间倒序，便于查看最新创建店铺。

### 4.5 操作按钮

每行需提供以下操作：

- 编辑
- 授权/重新授权
- 启用/停用

操作规则：

- 当授权状态为“未授权”或“失败”时，按钮文案显示“授权”。
- 当授权状态为“成功”时，按钮文案显示“重新授权”。
- 当当前状态为“启用”时，按钮文案显示“停用”。
- 当当前状态为“停用”时，按钮文案显示“启用”。

### 4.6 状态字段定义

#### 4.6.1 店铺状态

| 值 | 说明 |
|---|---|
| 启用 | 店铺参与同步、订单处理和后续履约流程 |
| 停用 | 店铺不参与同步和后续履约流程 |

#### 4.6.2 授权状态

| 值 | 说明 |
|---|---|
| 未授权 | 默认状态，尚未完成授权 |
| 成功 | 已完成授权，且当前授权记录可用 |
| 失败 | 授权失败或授权信息校验失败 |

#### 4.6.3 Token 验证结果

该字段保存最近一次令牌校验结果，前端展示为可读文本。

建议返回结构：

- `token_valid`: 布尔值，供程序判断。
- `token_message`: 文本，供页面直接展示。

建议文案：

- 成功：`Token令牌授权成功`
- 失败：`令牌无效，请检查`
- 未校验：`未验证`

### 4.7 数据与接口改造建议

店铺实体建议新增或补充以下字段：

| 字段 | 说明 |
|---|---|
| `authorization_status` | 授权状态 |
| `token_valid` | Token 是否有效 |
| `token_message` | Token 验证结果文案 |
| `last_authorized_at` | 最后授权时间 |
| `authorization_expires_at` | 授权到期时间 |
| `created_by` | 创建人 |
| `created_at` | 创建时间 |

建议接口扩展：

- `GET /api/v1/shops`
  - 新增筛选参数：`display_name`、`platform`、`enabled`
  - 新增排序参数：`sort_by`、`sort_order`
- `POST /api/v1/shops/{platform}/{shop_id}/reauthorize`
  - 用于授权或重新授权
- `POST /api/v1/shops/{platform}/{shop_id}/toggle-enabled`
  - 用于启用或停用

## 5. 订单列表需求

### 5.1 页面目标

订单列表页用于运营人员按状态和关键时间管理订单处理流程，支持批量选中、批量流转状态、同步物流、打印面单和导出数据。

### 5.2 状态标签栏

页面顶部需提供状态标签栏：

- 全部订单
- 待处理
- 配货中
- 已发货
- 待揽收
- 已妥投
- 已作废

规则：

- 默认进入页面时选中“全部订单”。
- 点击标签后，列表仅展示对应状态数据。
- 标签数量可展示对应状态订单数，若本阶段实现成本较高，可先不展示数量。

### 5.3 筛选条件

支持以下筛选：

| 筛选项 | 类型 | 说明 |
|---|---|---|
| 平台 | 下拉单选 | 选择订单所属平台 |
| 交易号 | 输入框 | 精确匹配或前缀匹配 |
| 订单付款时间 | 下拉单选 | 使用固定快捷选项 |

付款时间下拉选项：

- 今日
- 昨日
- 前日
- 近三天（不含当天）
- 近一周（不含当天）
- 近一月（不含当天）

时间筛选说明：

- “今日”按系统所在时区自然日计算。
- “昨日”指前一个自然日。
- “前日”指前两个自然日。
- “近三天（不含当天）”指 `T-3` 至 `T-1`。
- “近一周（不含当天）”指 `T-7` 至 `T-1`。
- “近一月（不含当天）”指 `T-30` 至 `T-1`。

### 5.4 操作按钮

页面顶部提供以下操作：

- 转入配货中
- 同步物流信息
- 打印面单
- 标记已发货
- 导出数据

状态限制：

| 操作 | 允许状态 |
|---|---|
| 转入配货中 | 待处理 |
| 同步物流信息 | 配货中 |
| 打印面单 | 配货中 |
| 标记已发货 | 配货中 |
| 导出数据 | 全状态可用 |

交互规则：

- 除导出外，其余操作需基于勾选订单执行。
- 若未勾选任何订单点击批量操作，应提示“请先选择订单”。
- 当勾选订单中包含不允许执行当前操作的状态时，应阻止提交并提示原因。

### 5.5 分页与勾选

表格需支持分页和勾选。

分页要求：

- 每页条数：50、100、500
- 默认每页条数：50

勾选要求：

- 提供“全选”复选框。
- 提供“反选”复选框或同等交互能力。
- 勾选后显示当前已选行数。
- 反选后也必须实时更新选中行数。

实现要求：

- 当前页全选仅作用于当前页数据。
- 若后续要支持跨页批量处理，需单独设计，此阶段先按当前页处理。

### 5.6 列表字段

订单列表需展示以下字段：

| 字段 | 说明 |
|---|---|
| 平台/站点 | 平台及站点信息，若暂无站点可先展示平台 |
| 店铺 | 所属店铺名称 |
| 交易号 | 平台订单号/交易号 |
| 客户ID | 平台买家标识 |
| 状态 | 待处理、配货中、已发货、待揽收、已妥投、已作废 |
| 平台状态 | 平台原始状态值 |
| 平台指定交运时间 | 平台要求的交运截止时间或承诺交运时间 |
| 国家(中) | 中文国家名称 |
| 买家自选物流 | 买家下单时选择的物流方式 |
| 订单核算金额(原币) | 订单原始币种金额 |
| 付款日期 | 买家付款时间 |
| 交运单号 | 运单号/交运号 |
| 交运时间 | ERP 执行交运的时间 |
| 剩余发货时间 | 距离平台最晚发货时间的剩余时长 |

### 5.7 Excel 导出字段

导出 Excel 需包含以下字段：

| 字段 | 说明 |
|---|---|
| 平台 | 平台编码或平台名称 |
| 店铺名 | 店铺展示名称 |
| 创建时间 | 订单创建时间 |
| 订单编号 | 平台订单号 |
| 国家二字码 | 国家 ISO 二字码 |
| 客户姓名 | 收件人或买家姓名 |
| SKU | 订单商品 SKU |
| 商品数量 | SKU 数量 |
| 商品销售单价 | 原币单价 |
| 币种 | 原币币种 |
| 物流渠道 | 系统匹配物流渠道 |
| 买家自选物流方式 | 买家选择的物流方式 |
| 最后发货期限 | 平台最晚发货时间 |
| 货运单号 | 运单号 |

导出规则：

- 支持基于当前筛选条件导出。
- 若存在勾选数据，优先导出勾选数据。
- 若未勾选数据，则导出当前筛选结果集。

### 5.8 数据与接口改造建议

订单实体建议补充以下字段：

| 字段 | 说明 |
|---|---|
| `shop_id` | 店铺 ID |
| `shop_name` | 店铺名称 |
| `site` | 站点 |
| `buyer_id` | 客户 ID |
| `buyer_name` | 客户姓名 |
| `biz_status` | 业务状态，使用本文件定义的状态 |

## 6. 订单关键时间字段定义

本项目必须严格区分以下四个时间概念。

### 6.1 付款日期

定义：

- 买家在平台完成支付的时间。

作用：

- 是计算剩余发货时间的起点。
- 是备货时效考核的重要依据。
- 是财务对账的重要时间字段。

### 6.2 剩余发货时间

定义：

- 从当前系统时间起，到平台最晚发货截止时间之间剩余的时间。

计算逻辑：

- `最晚发货时间 = 付款日期 + 平台备货期`
- `剩余发货时间 = 最晚发货时间 - 当前系统时间`

展示建议：

- 前端可展示为 `X天X小时`。
- 当剩余时间小于等于 0 时，应显示为超时或 0。

### 6.3 发货时间

定义：

- 卖家在电商平台后台成功填写运单号并确认发货的时间。

说明：

- 发货时间属于平台动作时间。
- 发货时间不等于仓库实际出库时间。
- 发货时间也不等于 ERP 交运时间。

### 6.4 交运时间

定义：

- 订单在 ERP 中执行交运操作的时间，即包裹交给物流商或推送至物流渠道的时间。

说明：

- 交运时间属于 ERP 内部履约节点。
- 交运时间通常早于或等于发货时间，但不强制要求完全一致。

### 6.5 四个时间节点关系

```text
付款日期
  ↓
最晚发货时间
  ↓
剩余发货时间 = 最晚发货时间 - 当前时间
  ↓
交运时间（ERP）
  ↓
发货时间（平台）
```

### 6.6 特别说明

- 对于仓发订单，发货时间应以平台真实发货时间为准。
- 不能使用虚假发货时间覆盖真实业务时间。
- 需要定期同步平台订单信息，刷新最晚发货时间和剩余发货时间。

## 7. 订单状态定义与流转

### 7.1 状态定义

| 状态 | 定义 | 触发条件 |
|---|---|---|
| 待处理 | 订单已成功拉入 ERP，等待下一步处理 | 拉单成功且无异常 |
| 配货中 | 已进入仓库拣货、打包流程 | 手动或系统转入配货中 |
| 已发货 | 已在平台确认发货或在 ERP 标记已发货 | 执行标记已发货 |
| 待揽收 | 已生成运单并等待物流商揽收 | 物流状态回传或交运后进入 |
| 已妥投 | 包裹已签收 | 物流商回传最终签收 |
| 已作废 | 订单取消或失效，不再履约 | 买家取消、超时关闭、人工作废等 |

### 7.2 状态流转

```text
待处理
  ↓
配货中
  ↓
已发货
  ↓
待揽收
  ↓
已妥投

待处理 / 配货中 / 已发货
  ↓
已作废
```

### 7.3 状态设计原则

- `状态` 字段表示系统统一业务状态。
- `平台状态` 字段保留平台原始状态值，便于排查差异。
- `已发货` 表示平台层面的发货动作。
- `待揽收`、`已妥投` 表示物流实际进展。

## 8. 前端交互要求

### 8.1 店铺管理页

- 筛选栏固定在列表上方。
- 操作按钮需根据状态动态显示文案。
- 授权状态、店铺状态建议使用标签展示。
- Token 验证结果使用纯文本展示，超长时支持悬浮提示。

### 8.2 订单列表页

- 顶部区域分为状态标签栏、筛选栏、批量操作栏。
- 表格首列为勾选列。
- 勾选后在批量操作栏附近展示“已选 N 条”。
- “全选”“反选”操作必须与表格勾选状态同步。
- 剩余发货时间建议按颜色区分风险：
  - 大于 24 小时：正常
  - 小于等于 24 小时：预警
  - 小于等于 0：超时

## 9. 验收标准

### 9.1 店铺管理

- 可按店铺名称、平台、状态筛选。
- 可按店铺名称、平台、状态排序。
- 列表完整展示需求字段。
- 可执行编辑、授权/重新授权、启用/停用。
- 授权状态默认值为“未授权”。
- Token 验证结果可正确回显最近一次校验结果。

### 9.2 订单列表

- 可按状态标签、平台、交易号、付款时间快捷筛选。
- 列表支持 50、100、500 分页。
- 支持全选、反选、选中计数。
- 支持按状态限制批量操作。
- 列表完整展示需求字段。
- 可按筛选条件或勾选结果导出 Excel。

### 9.3 业务口径

- 付款日期、交运时间、发货时间、剩余发货时间定义一致。
- 订单状态定义与流转一致。
- 页面字段名称、接口字段语义、导出字段口径一致。
